# P6 阶段 9B.6：英文 TN 的正则门控

**日期**：2026-10-04
**前置**：`p6-9b3-fst-and-gate.md`（门控可行性，有实测）、`p6-9b2-implementation.md`（TN 接线）
**结论**：门控**做完了并且有用**，但**不是任务书假设的那个形状**——判据照宽口径实现，
另外加了一张 15 词的封闭表，因为纯形状判据**不可能**是可靠的过近似；而且
**任务书要求的那条不变量在一般意义上不成立**，我把它换成了能成立的三条并把原条保留为其中之一。
实测：门控 2.8 µs / 950 字符（TN 43 ms），普通散文句子 **10/10 跳过**，
技术文档句子 83/127 触发（其中 16 条是误报），wasm **+977 B**，
`cargo test` 188 → **197** 全绿。

---

## 一、门控放在哪

新模块 `crates/phonemize/src/backends/tn_gate.rs`，公开一个函数：

```rust
pub fn needs_normalization(text: &str) -> bool
```

**独立模块而不是 `wetext_tn.rs` 里的一个函数**，理由是这个 crate 的规矩：埋在 worker
里的逻辑没法测。`tn_gate` 是纯函数、零状态、不碰 FST，单元测试和集成测试都能直接调。
`wetext_tn.rs` 是「引擎与字典协议的接缝」，门控不是接缝上的东西，它是接缝**前面**的东西。

接线在 `pipeline.rs::phonemize_en`，位置就是唯一有意义的位置——数字那一步**之前**：

```rust
let with_numerals: Cow<'_, str> = match tn {
    Some(tn) if tn_gate::needs_normalization(&normalized) => Cow::Owned(
        tn.normalize(&normalized).unwrap_or_else(|_| numbers_to_english(&normalized)),
    ),
    Some(_) => Cow::Borrowed(&normalized),
    None => Cow::Owned(numbers_to_english(&normalized)),
};
```

`Cow` 而不是 `String`：跳过那条路径是热点，`normalized.clone()` 虽然只有 ~100 ns，
但克隆一个 710 字符的字符串正是这道门想省的那类动作。

**`None` 分支一行没动。** 任务书写得很清楚：调用方没 `prepare` 时仍走原来的
`numbers_to_english` 回退，门控不介入那条路径。这是对的，理由不是"保守"而是**语义**：
那个分支今天存在是因为英文的音素不需要字典，把门控塞进去等于把「没准备」和「没活干」
两件事合并，而它们会有不同答案（`3:30pm` 在没引擎时要走回退，门控说"有活干"，
但那活干不了）。

### 跳过时返回 `normalized` 而不是 `text`

同一个东西吗？不是。`normalize_punctuation` 总是先跑（第一期就有的步骤），
门控看到的是**它之后**的文本。所以跳过时返回的是 `&normalized`。这一点在
`phonemize_en` 的注释里原本就写着，门控没改它。

## 二、判据的最终形状

```rust
pub fn needs_normalization(text: &str) -> bool {
    text.bytes().any(|b| b.is_ascii_digit())      // 1. ASCII 数字
        || text.chars().any(is_normalized_symbol)  // 2. symbol.tsv 的 22 个字符
        || has_capital_run(text)                   // 3. 连续 2 个大写
        || has_terminated_abbreviation(text)       // 4. 1–5 字母 + `.` + 后面还有字
        || contains_shape_less_abbreviation(text)  // 5. 15 词的封闭表
}
```

### 2. 符号集比任务书多三个

任务书列了 19 个（`& # @ § ™ ® © _ % * + / = ^ | ~ $ £ € ₩`），
上游 `whitelist/symbol.tsv` 是 **22 行**——`¥`、`°`、`º` 也在里面
（`°` 和 `º` 是两行、同一个词）。三个都进了。多算了两个误报源，少算了三个漏报源。

### 4. 「后面还有字」的准确含义

`dot + 1 != bytes.len()`——即 `.` 不是文本的最后一个**字节**。
调用方传进来的是句子（见 §三.3），所以这等价于「句末的 `.` 不算」。

**这条规则本身就是个已知的漏**：`Contact Dr.` 里的 `.` 是句末，
但语法确实把 `Dr.` 标成 `whitelist` 并读成 `doctor`。§四.3 有实测。
不改成「句末也算」的理由是**代价**：`the mat.` / `It is.` 这类句末短词占了散文
很大的比例，改完之后门控在真实散文上基本不省任何东西。

### 5. 那张 15 词的封闭表（偏离任务书的地方）

任务书的判据里没有这一条，我加了，因为**不加就是静默错音**：

| 输入 | 门控（纯形状） | 语法 | 后果 |
|---|---|---|---|
| `See you on Mon morning.` | 跳过 | `Mon` → `Monday` | 读成 "mon" |
| `I saw Mrs Smith.` | 跳过 | `Mrs` → `Misses` | 读成 "mrs" |
| `Martin Luther King Jr spoke.` | 跳过 | `Jr` → `junior` | 读成一个字母 |
| `Tu` / `Th` | 跳过 | `Tuesday` / `Thursday` | 同上 |

这些词**没有任何形状**可判：`Mon` 就是一个普通的首字母大写三字母词，
和 `Tom`、`New`、`Sat`（`Sat` 也是）没有区别。表里 15 个词分别是上游
`tn/english/data/whitelist/alternatives.tsv` 的**全部**无点键
（`Mon Tue Wed Thu Thur Thurs Fri Sat Sun Tu Th Mr Mrs Ms`，`TV` 走判据 3）
再加 `tts.tsv` 里的 `Jr`。三个（`Tue Thu Thurs`）实测**不被这份语法标**
——留着是因为「语法以后要标」是一种它不需要声明的变化，早判只代价一次白跑。

**这张表不是「缩写清单」，它不可能完整**，§四.2 有数字。文档注释和
`p6-9b6-tn-gate.md` 都写在代码里了。

## 三、为什么手写扫描，不用 `regex`

任务书说「`Cargo.toml` 里已经有 `regex`，但那是 vendored contractions 用的，
不要因为这个就顺手用它——**要量体积**」。量了：

| | wasm |
|---|---|
| 加门控之前 | 6,041,531 B（测试里钉死的值） |
| 加门控之后 | **6,042,508 B** |
| 差 | **+977 B** |

977 字节。判据全是「有没有这类字符」和「这个 token 是不是这个形状」，
十几行字节算术、一个 `matches!` 跳转表、零分配、零依赖。
`regex` 虽然已经在依赖图里（contractions + `piper-plus-g2p`），但它会链接进一个
编译好的自动机，而且它跑的时机是**每条英文句子**，包括那些里面什么都没有的。
一道过滤器是放 DFA 的最差位置。

**没有引入任何新依赖**，`Cargo.toml` 一行没改。

### 耗时（release 原生，950 字符）

| | 950 字符 |
|---|---|
| `needs_normalization` | **0.0028 ms**（3 ns/字符） |
| `Normalizer::normalize`（Tagger + Verbalizer） | **42.9 ms** |

约 **15,000×**。8063 字符上门控 0.0212 ms，线性。

### 效果：按**句子**度量，不是按段落

**这一条是本次最重要的事实更正，见 §四.1。** 管线的单位是句子
（`lib/models/audio.ts::planPieces` 由 `synthesize` 按 `segmentSentences`
的粒度调用），所以按句子度量才是对的。

| 语料 | 句数 | 门控触发 | 其中误报 | 跳过 | 漏掉实体 |
|---|---|---|---|---|---|
| 手写普通叙事英文（无数字/缩写/符号） | 10 | 0 | 0 | **10** | 0 |
| `crates/phonemize/src/backends/wetext/README.md` | 44 | 36 | 4 | 8 | 0 |
| `crates/phonemize/README.md` | 47 | 32 | 9 | 15 | 0 |
| pi 的 README（`node_modules` 里那份） | 26 | 15 | 3 | 11 | 0 |
| **合计** | **127** | 83 | **16** | 44 | **0** |

普通散文句子 **10/10 跳过**（这正是门控存在的理由）；技术文档句子只有
32% 跳过，因为那些句子真的在讲数字和符号——触发是**正确**的，不是误报。
误报率 16/127 = 12.6%，和 9B.3 在 34 条语料上量到的 ~11% 一致。

15,000× 的差距 × 普通散文 100% 的跳过率 = 普通散文的英文 TN 成本
基本归零。

## 四、不变量测试：任务书要求的那条不能成立

### 4.1 要求的形状与真实的形状

任务书要求：

```
gate(text) == false  ⇒  tagger 对这段文本的输出只含 `w` 和 `p` 两个类
```

**这条在一般意义上不成立**，而且不是实现没写好——是判据的性质决定的。
`whitelist` 类就是上游的一张字符串表（`tts.tsv`，3,050 行），
语法把它读成 string map。**string map 没有形状**：`Uusi`、`Whyld`、`Vrba`、
`xCo`、`Γ` 都是表里的键，都是普通词的样子。实测：

- `tts.tsv` 里**没有**数字、**没有**点、**没有**大写连写的键：**1,137 个**；
- 这 1,137 个里被 tagger 标成非 `w`/`p` 类的：**1,137 个（全部）**；
- 门控漏掉的：**1,127 个**。

所以「纯形状门控 + `gate false ⇒ 只有 w/p`」是一个**不可满足**的组合。
上一轮 9B.3 在 34 条语料上量出「召回 15/16」，那 16 条是**手挑的**语料；
把语料换成上游自己的白名单，召回立刻掉到 1,137 里的 10 条。

### 4.2 这个洞有多大：按**能不能听出来**度量

光数「漏了多少键」会高估问题，因为这些键的映射大多是**转成大写**
（`isCf` → `ISCF`、`Achs` → `ACH's`），而这条管线里全大写本来就会被 G2P
按字母拼读，两边落点相同。所以量的是音素：

方法：对每个漏掉的键，比较
`phonemize_en(key, g2p, None)` 与 `phonemize_en(语法输出, g2p, None)`。
**两边都不带 `tn`**，否则门控会把自己关掉，测出来必然是 0。

> 第一次测出来是 0，就是这个错误：一侧开着引擎、另一侧门控把它关了，
> 两边都跑在"跳过"路径上，答案是构造出来的。这一条写进代码注释了
> （`tests/tn_gate.rs::skipping_is_the_same_as_the_pipeline_without_the_engine`）。

| | 数量 |
|---|---|
| 无形状且被 tagger 标记的键 | 1,137 |
| 门控漏掉 | 1,127 |
| 其中**音素不同** | **182（16%）** |
| 音素相同的 | 945（91% 是专有名词，转大写与不转大写拼读相同） |

182 条里有：

- **希腊字母 48 条**（`Γ → gamma`、`θ → theta`）——没跑语法时希腊字母被
  `segment_text` 归到 `other` 直接丢掉，是**静音**。英文 TTS 里基本不会出现，但如果出现，
  跳过 = 少念一个词。
- **`World War I` → `World War one`**——真实文本里会出现（历史材料）。
- 其余是专有名词 + 所有格/大写变换（`Agco → AGCO`、`Aes → AE's`）。

**没有一条是普通英语词**：和 `/usr/share/dict/words` 取交集，1,137 个键的
小写形式里有 68 个在词典里，几乎全是生僻词（`ceorl`、`epos`、`pyx`），
有实际语料意义的只有 `mon`/`mr`/`mrs`/`sat`/`sun` 这一类——**都已经在 §二.5 的表里**。

### 4.3 第二个洞：句末的点

| 输入 | 语法 | 门控 |
|---|---|---|
| `I spoke to Dr.` | `doctor` | 跳过（漏） |
| `I spoke to Mt.` | `Mount` | 跳过（漏） |
| `I spoke to Gov.` | `governor` | 跳过（漏） |
| `I spoke to Bldg.` | `Building` | 跳过（漏） |

`Dr. Smith` 是好的（点后面有字）；点在句末就不认。代价 ~4 类常见缩写，
收益是 `the mat.` / `It is.` 不被误判。**这个交易值得**，但它是个漏，写在这里。

### 4.4 实际交付的三条不变量

`crates/phonemize/tests/tn_gate.rs`，70 条语料（每条都带「为什么在这儿」的注释，
逐条覆盖：普通散文 32 条、实体 15 条、electronic 3 条、缩写 7 条、
无形状白名单键 5 条、符号 6 条、非实体大写 3 条）：

1. **`the_gate_never_skips_anything_the_tagger_found`** —— 任务书要求的那条，
   对**这份语料**成立（27 条被跳过，全部只有 `w`/`p`）。语料自带
   「至少 25 条被跳过」的断言，否则一条全触发的门控也能过。
2. **`the_gate_never_skips_text_normalization_would_have_changed`** —— 比 (1) 强：
   跳过意味着**整个引擎**原样返回。这条是 (1) 想表达的东西，(1) 只是它的代理。
   它也能抓住 (1) 漏的情况（tagger 匹配不到任何东西时返回原文，verbalizer 再跑一遍）。
3. **`skipping_is_the_same_as_the_pipeline_without_the_engine`** —— 音素层面的端到端：
   `phonemize_en(text, g2p, Some(tn))` == `phonemize_en(语法输出, g2p, None)`。
   右边 `tn = None`，门控碰不到它，所以这条**能真的失败**。
4. 另外两条：`the_fallback_the_gate_bypasses_is_a_no_op_on_every_skipped_entry`
   （任务书要求「用测试证明」的那个前提：被跳过的语料里没有数字，
   且 `numbers_to_english` 对它们是恒等）和 `a_paragraph_..._unchanged`（整段端到端）。

**这四条合起来是门控的正当性来源**，也是「门控不会变成第二份会漂移的定义」的保证：
漂移会让测试红，而不是让线上静默退化。

## 五、不确定与没做的

1. **`/usr/share/dict/words` 是 macOS 的，不是可复现的语料。**
   §四.2 的交叉验证只做了一次，没有进 CI。结论（漏掉的都是生僻词/专名）
   来自这一次人工比对，不是自动化断言。
2. **§三的散文语料是手写的。** 仓库里没有普通叙事英文——所有文档都是中文或技术性的，
   所以我写了 10 句普通叙事英文作为样本。它没有数字、没有缩写、没有符号，
   这是**构造出来的**，不能当作"真实输入分布"的估计。技术文档那三份是真的，
   127 条里 117 条来自它们。
3. **段落级的误报很严重**（同一批文档：26 段里 24 段触发，只跳过 2.3% 的字符），
   因为 `.` + 后面有字 = 「这段是多句的」几乎恒真。**管线按句子调用所以不影响现在**，
   但如果有调用方把整段交给 `phonemize_en`，门控基本不省东西。这条是判据 4 的
   直接后果，任务书要求「宁可宽」，我照做了，但代价在这里。
4. **`p6-9b3` §二说的「普通散文里约 83% 的句子跳过、约 11% 白跑」成立**，
   我量到的是 10/10 跳过（普通散文）和 12.6% 误报（含技术文档）。两者不矛盾。
   但**那个文档没有说段落级会退化到 7.7%**，这是本次补上的。
5. **想彻底关掉 §四.2 的洞，唯一的路是把白名单交给门控**：把
   `tts.tsv` + `alternatives.tsv` 的键作为一张表（~40 KB 原文，做成排序静态数组
   ~25 KB）随字典协议取进来，门控查表。这需要一个新的构建期生成脚本
   + 一个新资产 + 一次体积评估，**不在本次范围**。如果做了，门控就不再依赖
   「(2) 中的 15 词表」这个经验判断，`SHAPE_LESS_ABBREVIATIONS` 可以整段删掉。
   建议：**做**，如果英文管线要上生产（现在生产走 kokoro-js 的 espeak，不走这里）。
6. **`backends/wetext_tn.rs` 的 "What it costs at runtime" 段落是错的**，
   而且**在本次改动之前就错了**（它写「没有 ASCII 数字的句子 ~0.001 ms 早退」，
   那正是 9B.2 §3.1 修掉的那个 bug 的副产品；9B.2 §3.3 自己更正过）。
   我改了它，因为门控就在那段话描述的位置上，留着等于用错误的前提描述我的改动。
   这是本次唯一一处改动别人未提交代码的地方。
7. **`p6-9b3` §五把这条不变量称作「允许第一层存在的前提」**，我同意，
   但 9B.3 没有量过它在**上游自己的白名单**上的召回。§四.2 补上了，
   结论是它在那个语料上不成立。设计的其余部分（两层、先门控后 tagger）仍然成立。
