# 日语 G2P 前端重建 spec（2026-10-05）

**状态**：调研完成；P0（对齐主流共识）**已于 2026-10-05 实施**（§4）；P1（音素集对齐训练分布）待拍板。
**触发**：三条 `vocabulary-mismatch`（`・`、`及`、`詳`）与同一原因造成的静默错读（`語る`→カタリル、`進める`→ススムメル…）。
**原报告的正文是第三方新闻内容**：报告本身不入库（开源风险），等效的合成用例及其参考读法
记录在 `crates/phonemize/tests/fixtures/ja-reference.json`（如 `その被害は…及んでいる`、
`彼は機械の仕組みに詳しい`、`サーバ・クライアント・ネットワークについて`）。
**取证方式**：本机 `pip install misaki[ja] / pyopenjtalk / pykakasi` 真跑 + 各版本 wheel 反编译 + lindera 直读词典字段。未复核的结论均标注出处。

---

## 0. 摘要

1. **我们按「脚本 run」分段再逐段查词典，是错的**。主流（pyopenjtalk / VOICEVOX / Style-Bert-VITS2 / misaki）一律把**整句**交给形态素解析器。这一个缺陷同时产出「报错的汉字残留」和「不报错的错读」（語る→カタリル、進める→ススムメル…），8/8 句普通日文都与整句参考不一致。
2. **我们用了 `reading`（読み），主流一律用 `pronunciation`（発音）**。`東京は`→トーキョー**ワ**、`こんにちは`→コンニチ**ワ**、`学校へ`→ガッコー**エ**。**我们的 IPADic 资产自带 `pronunciation` 字段，换字段是一行改动**（此前调研中的「需要换 UniDic / 加助词覆盖表」是错误结论，见 §3.6）。
3. **`・` 当作停顿有三家先例**（§2.4）：OpenJTalk 把它变成与 `、` 完全相同的 `pau`；Style-Bert-VITS2 显式 `"・": ","`；misaki 则删掉它并在前一个词后插空格。Kokoro 只认 ASCII 标点 + 空格。

## 1. 训练目标：Kokoro v1.0 的日语喂的是哪一代 misaki

`misaki` 的 ja 有**两代，音素集完全不同**（本机各版本 wheel 实测）：

| 版本 | 日期 | ja.py | 汉字→假名 | 假名→IPA | 音高 |
|---|---|---|---|---|---|
| `0.3.5`–`0.7.x`（含 `0.6.0`） | 2025-01-13 起 | 420 行 | fugashi + **UniDic(`pron`→`kana`)** | 自研 **HEPBURN** 表（84 键） | 无 |
| `0.9.4` | 2025-04-05 | 356 行 | pyopenjtalk（+ 可选 cutlet） | **M2P** 表（193 条） | 追加 `_ ^ - j` 串 |

- `0.6.0` 与 `0.7.4` 的 `ja.py` **逐字节相同**；`0.9.4` 的 `ja.py` 默认 `version='cutlet'`，且 wheel 里带 `cutlet.py`。
- **misaki README 原文**：first gen "mainly relies on cutlet => fugashi => mecab => unidic-lite … **before any Kokoro model had started training**"；second gen "**now** uses pyopenjtalk with full unidic, enabling **pitch accent marks**"。
- **Kokoro v1.0 = 2025-01-27**（HF Releases 表，SHA `496dba11`）；日语 5 音色 jf_alpha/jf_gongitsune/jf_nezumi/jf_tebukuro/jm_kumo（VOICES.md，后四个训练数据只有分钟级、grade C，页面自述 "non-English … due to **weak G2P**"）。
- ⇒ **v1.0 的日语训练目标是 first gen（cutlet/UniDic + HEPBURN）**。我们现在用的 `kuroshiro + M2P(改)` **两代都不是**。
- ⇒ **不要加音高**：first gen 不输出；second gen 的 `_ ^ -` **不在 v1.0 词表**（`vocab-v1.txt` 只有 `↓ → ↗ ↘`，那是中文声调符号），会被 tokenizer 静默删掉；`j` 虽在词表但会污染音素串。

## 2. 主流共识（每条给可复现证据）

### 2.1 汉字→假名：整句一次，绝不按脚本分段
| 前端 | 位置 | 做法 |
|---|---|---|
| misaki | `ja.py` `pyopenjtalk.run_frontend(text)` | 整句 |
| Style-Bert-VITS2 | `nlp/japanese/g2p.py:111` `run_frontend(norm_text)` | 整句（子代理实测，未复核） |
| VOICEVOX | `tts_pipeline/njd_feature_processor.py:96` `run_frontend(text)` | 整句（同上） |
| ESPnet | `espnet2/text/phoneme_tokenizer.py:87` `pyopenjtalk.g2p(text)` | 整句（同上） |
| misaki cutlet | `cutlet.py` MeCab 后按 `char_type` 合并 | 整句 |

本机 `pyopenjtalk` 实测：`詳しい→クワシイ`、`語る→カタル`、`進める→ススメル`、`及ん→オヨン`；`run_frontend` 里 `pos='形容詞' mora_size=4` —— 整句下这些都**不是**问题，问题只在我们的分段步骤。

### 2.2 用 発音(`pron`)，不是 読み
- pyopenjtalk 实测：`東京は→トーキョーワ`、`こんにちは→コンニチワ`、`学校へ→ガッコーエ`、`調査→チョーサ`。
- misaki `ja.py`：`word['pron']`（0.9.4）/ `w.feature.pron or w.feature.kana`（0.6.0）；SBV2 `parts["pron"]`。
- 反例（用 reading 就错）：pykakasi `彼は学校へ行った → カレハ…`（は→ha）；espeak-ng ja `これは → ko̞ɽˈe̞hä`（恒读 ha，且无形态素层）（子代理实测，未复核）。

### 2.3 标点与停顿
- OpenJTalk 系把标点变成音素层 `pau`；VOICEVOX `is_pause = contexts["f1"] == "xx"`（子代理实测，未复核）。
- misaki：`PUNCT_MAP`（`。`→`.`、`、`→`,`、`「」`→`“ ”`）+ `PUNCT_STOPS` 后加空格 → 交给 Kokoro 的只有 **ASCII 标点 + 空格**。
- **Kokoro v1.0 词表约束**（`crates/phonemize/data/vocab-v1.txt`，实测）：有 `! " ( ) , . : ; ? — … …` 和空格；**没有** `、` `。` `・`，也没有 `_ ^ - ↑`。⇒ 停顿只能落到 ASCII 标点或空格。

### 2.4 `・`（U+30FB）
| 实现 | 行为 | 出处 |
|---|---|---|
| OpenJTalk | `run_frontend` 给 `pos='記号' pron='、' mora_size=0`；`extract_fullcontext("あ・い")` 与 `"あ、い"` **完全相同**（`sil a pau i sil`） | 本机 pyopenjtalk 实测 |
| Style-Bert-VITS2 | `normalizer.py` 显式 `"・": ","` | 子代理（未复核） |
| misaki（两代） | 删掉该 token，并把前一个词的尾随空格设为 `' '`；0.6.0 另有字符表项 `'・': ' '` | 本机 0.7.4 实测 + 源码 |
| UniDic | `kana='・' pron=''`（空读音） | 子代理（未复核） |
| espeak-ng ja | 念成 "Japanese letter" | 子代理（未复核） |

### 2.5 促音/長音/鼻音/無声化
- 促音 `ッ→ʔ`、長音 `ー→ː`、`ン→ɴ`：misaki 的 M2P 与 HEPBURN 都在**假名→IPA 表**里解决；first-gen misaki 的 `ン` 是**上下文相关**（`m` / `n` / `ŋ` / `ɲ` / `ɴ`），我们的表是扁平 `ɴ`。
- 無声化：OpenJTalk 写在 pron 里（`です → デス’`），misaki/SBV2 都**显式丢弃**。⇒ 跟 misaki 一致 = 不加。

## 3. 我们现在的偏离（实测）

1. **按 run 分段**（`text.rs::segment_text` 把 Han/Kana 分开 → `pipeline.rs::phonemize_ja` 逐 run 调 `read_as_katakana`）。
   8 句普通日文的读音 **8/8 与整句参考不同**；两种形态：汉字残留报错（詳/及/読）、静默错读（語る→カタリル、起きて→オコシキテ、食べる→ショクベル、書きます→ショキマス、買って→ガイッテ、行く→クダリク…）。
   **这是继承来的**：被 phase 8 删除的 `lib/models/phonemize/japanese.ts:521-524` 同样逐 run 调 `textToKatakana(run.text)`；旧链路 tokenizer 静默删掉残留汉字，所以一直没被发现。
2. **用 `reading`** ⇒ `は`/`へ` 助词读成 ハ/ヘ（`deɴwaha`、`toukjouhaniʔpoɴnoɕutodesu`），而 parity 语料把这个错误钉住了。
3. **`・` 报错**（与切 run 无关，整句查词典也一样）。
4. **没有词间空格**：misaki 的输出是 `hoɴɕi ɕɨːkaɴ posɨto …`（first gen 每个普通词后带空格；M2P 版按 TAILS 规则插空格），我们全拼接。
5. **音素表**：我们 193 条 = 0.9.4 的 M2P（`ᶄᶃᶀᶁᶆᶈᶉ` 那批改成 `kja/kwa`，因为 v1.0 词表里没有）。
   本机对 first-gen misaki 逐条实测：**81 条一致 / 112 条不一致**（其中 8 条是孤立小假名，misaki 输出空）。系统性差异：`ウ u/ɯ`、`ス su/sɨ`、`ザ za/ʣa`、`ヒ hi/çi`、`フ fu/ɸɯ`、`ラ ra/ɾa`、`ワ wa/βa`、`ニ ni/ɲi`、`キ kʲi`、`キャ kʲa`… **两组都完全落在 v1.0 词表内**，词表无法仲裁。
6. **`pronunciation` 字段其实有**：asset 内 `metadata.json` 的 schema 是 13 个字段，最后一项就是 `pronunciation`；lindera 实读：`こんにちは reading=コンニチハ pronunciation=コンニチワ`、`は ハ/ワ`、`へ ヘ/エ`、`調査 チョウサ/チョーサ`、`学校 ガッコウ/ガッコー`。**与 pyopenjtalk 的 pron 一致**（IPADic 与 OpenJTalk 同属 NAIST 谱系）。

## 4. P0：对齐共识的修复（**已实施**，2026-10-05）

实施后的实际形态，与本节最初的草稿有两处不同，两处都是实施中量出来的：

1. `g2p/ja/segmenter.rs`：`READING_FIELD` → `PRONUNCIATION_FIELD`（值 `pronunciation`），
   `JaToken.reading` → `JaToken.pronunciation`。与草稿一致。
2. `pipeline.rs::phonemize_ja`：词典**一次看一个「汉字＋假名」run**，而不是整段。
   为此新增 `text.rs::segment_japanese`（把 Han 并入 Kana 再切 run）。
   - 草稿的「整段一次过词典」会**吃掉标点后的空格**：lindera 像 MeCab 一样跳过空白，
     而 `、`→`", "` 的那个空格过去是靠标点 run 保留的；实测 `こんにちは,せかい` 丢了空格。
   - 反过来，按「汉字＋假名 run」切又比合并成一个大 CJK run 更准：标点不送进词典，
     而标点在 OpenJTalk 里本来就是 `pau`（分段边界）。
3. `・` → 停顿：落在 `text.rs::normalize_ja_punctuation`（ja 自己的那一半，共享的
   `normalize_punctuation` 不动），落成 `, `——用户拍板的“作为停顿”，与 OpenJTalk 把 `・`
   当 `、`、Style-Bert-VITS2 的 `"・": ","` 一致；misaki 的做法（删掉、留空格）是不带
   停顿时备选。
4. 测试：先写失败测试（`reads_kanji_through_the_dictionary` / `does_not_warn_about_text_with_no_latin_in_it`
   / `a_middle_dot_becomes_a_pause` / `the_pipeline_matches_the_reference_g2p`），确认红灯
   （`・`/`及`/`詳` 报 vocabulary-mismatch，`経営` 读 ケイエイ）后实现。
5. 语料：按用户决定**重写为参考值、丢掉 js 基线**——`ja-parity.json` 删除，新增
   `ja-reference.json`（62 样本）+ `scripts/check/check-ja-reference.py`（用 pyopenjtalk
   重算 `kana`/`expected`，可 CI 之外的开发期跑）。

**实施中量出来的两个新事实**（草稿里没有）：

- **IPADic 的 pronunciation 不收合エ段长音**（経営 → ケイエイ，参考词典是 ケーエー），
  但收合ウ段（チョウサ → チョーサ）。这是词典差异，语料用 `gap` 字段把 `経営` 记成
  唯一条目，而不是把当前限制写死成期望值。
- **OpenJTalk 的 NFE 会读不规则助数詞/日期**（`二日` → フツカ、`一本` → イッポン，
  我们读 ニニチ/イチホン）。样本因此避开了这类词，缺口记在 §6。

## 5. P1：对齐训练分布（大改动，需 A/B）

- 换 **HEPBURN 表**（first-gen），补 `ン` 上下文规则，词间空格，标点向 misaki 靠（`「」`→`“ ”`）。
- 词典**可以继续用 IPADic**（体积不变）。已知残留差异：① 形容词イ長音（我们 pron `クワシイ`，UniDic `クワシー`；与 OpenJTalk 一致）；② 分词差异（IPADic vs unidic-lite）；③ counter sandhi（`一本` 我们 → イチホン，pyopenjtalk → **イッポン**，OpenJTalk 在 NFE 层解决）——都要单独开条目。
- 验收：用 `jf_alpha` 对同一批句子做 A/B 试听 + 与 misaki 0.6.0 输出逐字符对照。
- 风险：这是**换音素集**，全量日语输出都会变；不做听力确认不上线。

## 6. 残留缺口（P0 之后仍然存在）

按发现顺序，三条都属于「词典/参考链比我们多一层」：

1. **エ段长音**：IPADic 的 pronunciation 收合ウ段（チョウサ→チョーサ）但不收合エ段
   （経営 我们 ケイエイ，参考 ケーエー）。影响面很广（先生/学生/英語/平成/経験/時計/携帯…），
   语料里 `経営` 是唯一的 `gap` 条目。修法是 P1 的词典选型，不是加文本规则。
2. **NFE 的不规则读数**：OpenJTalk 在 NFE 层把 `二日` 读 フツカ、`一本` 读 イッポン
   （助数詞的促音/连濁），我们按词典逐词读（ニニチ/イチホン）。
3. **無声化**：OpenJTalk 的 `pron` 里写 `’`（例：学生 → ガク’セー），misaki 两代都丢掉。
   我们也不输出，与训练分布一致，暂不处理。
4. **音素集本身**（P1 的核心问题，见 §5）：v1.0 日语训练用 misaki first gen
   （cutlet/UniDic + HEPBURN），我们仍是 M2P 表，193 条里 112 条不同。

另外一条不要做：**音高标记**。first gen 不输出；second gen 的 `_ ^ -` 不在 v1.0 词表里
（词表只有 `↓ → ↗ ↘`，那是中文声调），会被 tokenizer 静默删掉；`j` 虽在词表但会污染音素串。
